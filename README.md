# DAYZ DROP

Магазин одежды в Telegram (Узбекистан, сумы): бот + мини-приложение + админ-панель. Всё на бесплатных сервисах.

## Как устроено

```
Покупатель ──► Telegram-бот ──► Мини-апп (GitHub Pages, webapp/)
                    │                    │  запросы с подписью Telegram
                    ▼                    ▼
              Сервер бота + API (Render free, bot/)
                    │
                    ▼
              База Postgres (Render free)
```

- `webapp/` — мини-апп, чистый HTML/JS без сборки:
  - `app.js` — ядро, навигация (у каждой вкладки свой стек и кнопка «Назад»), экраны покупателя
  - `admin.js` — экраны админки, `effects.js` — эффекты в духе React Bits (переписаны без React)
- `bot/` — Python (aiogram 3 + aiohttp + SQLAlchemy):
  - `texts.py` — **все тексты бота**, меняются без правки кода
  - `services.py` — заказы, оплата, доставка, склад, уведомления
  - `loyalty.py` — регистрация, баллы, купоны, награды
  - `finance.py` — касса, прибыль, выгрузки в Excel, бэкап
  - `tasks.py` — напоминания об оплате, автоотмена, вечерний отчёт, рассылки
  - `api.py` / `api_admin.py` — API мини-аппа; `shop_bot.py` / `admin_bot.py` — магазин и админка на кнопках бота
- Фото товаров и чеки хранятся в самом Telegram (по `file_id`), отдельное хранилище не нужно.
- Новые колонки в базе добавляются сами при запуске — данные не теряются.

## Оплата без ИП: карта или наличные

**Картой.** Покупателю выдаётся одна из активных карт (по очереди — выручка делится между админами).
Он переводит и присылает чек → оба админа получают его с кнопками **«Деньги пришли / Не пришли»**.
Через `remind_hours` бот напоминает об оплате, через `cancel_hours` снимает заказ и возвращает вещи на склад.

**Наличными** (если способ доставки это разрешает): заказ сразу «Подтверждён», деньги принимаются при выдаче.
Кнопка **«Не выкупил»** отменяет заказ и оставляет этому покупателю только предоплату.

Подтверждать оплату и менять статусы могут только админы (`ADMIN_IDS`), каждый запрос мини-аппа проверяется по подписи Telegram.

## Что ещё есть

- **Склад:** приход с ценой закупки, списание, инвентаризация, журнал движений, предупреждение «заканчивается».
- **Касса:** выручка по картам и наличным, себестоимость, расходы, прибыль за день/неделю/месяц, выгрузка в Excel.
- **Бонусная программа:** необязательная регистрация, баллы за регистрацию и с каждого полученного заказа, обмен баллов на купоны-награды, ручные бонусы и бонус всем.
- **Промокоды:** процент, сумма или вещь в подарок, лимиты, срок действия.
- **Покупатели:** история, заметки, отметка «не выкупил». **Рассылки** дропов всем или зарегистрированным.
- **«Сообщить о поступлении»**, избранное, оценка заказа, метки New / Хит / Скоро, зачёркнутая цена, замеры.
- **Двое админов:** «взять в работу», история заказа — кто и что сделал. Вечером — отчёт и бэкап базы в чат.

## Деплой

1. **Мини-апп** — GitHub Pages, публикуется сам через Actions при пуше в `main`.
2. **Сервер** — Render (`render.yaml`), вебхук бот ставит сам. Переменные: `BOT_TOKEN`, `DATABASE_URL`, `ADMIN_IDS`, `WEBAPP_URL`.
3. В `webapp/config.js` указан адрес сервера; в `index.html` у файлов есть `?v=` — меняй при обновлении, чтобы Telegram не показывал старую версию из кэша.

## Локальный запуск

```bash
cd bot
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\python main.py
```
Без `DATABASE_URL` используется локальный SQLite, бот работает через polling (не запускай его, пока работает сервер на Render).
